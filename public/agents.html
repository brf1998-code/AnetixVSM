Agent settings

Improvement board

Which model does each job, and what the agents read before they touch this company's modules. Managers can change both; the platform principles are fixed and shown for reference.

Models

Propose
One call per request: reads the module, drafts the proposal, picks look-and-feel or how it works, and names the screen. Also restates the requirement before a functionality build, draws the diagrams and answers in a module's chat.
Build
The agent that edits the module files, many turns with file tools. Most of the spend.
Review
The independent check of a functionality build's diff. One call, diff only.
Prices are per million tokens, input / output. Every job runs on Fable 5.1 or Opus 5.5. Leave a job on the platform's model unless there is a reason to pin it: the platform's model is the one the model assessment on the admin page settles on, and a pinned job stays out of the live A/B test there. Per-run and monthly caps still apply.

What happens when a request arrives (read it at once, photos) is on the company's Settings page, with people, printers and the wall sign.

What the agents read

Sent with every proposal and build, in this order: platform principles, then this company's docs, then the module's reference doc. Plain markdown. Keep them short and concrete; the agent follows what is written here more reliably than anything in the feedback text.
