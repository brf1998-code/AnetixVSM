Loop health the platform's own numbers: is the loop turning, how fast, where it stops

Counts are for the window; open items, what is waiting, and the quiet stretch are as of now. Same shift means feedback to floor within 8 hours. To floor runs from the feedback item to the deploy (the oldest item in a batch). Manager wait is proposal drafted to decided, then ready to deployed. Stops are where builds stopped: the platform's own checks (gate), the reviewer, the tests, or something else. Quiet is days since the last reviewer or test stop, gate stop, and rollback; a long quiet stretch is the signal to try a cheaper build model. Edited is how many approved proposals the manager changed first (on the record since Sept 19). Decision times before the record use the run's start.

Data requests changes the floor asked for that need ERP data the connection does not give yet. The manager only sees "waiting on data".

Module library what ships in the repo, before any company changes it

Every module starts here as version 1. Start tour opens the module on a company's floor and walks a new operator through its screens, step by step, with the feedback button as the last stop. The tour is tour.json inside the module; agents can keep it current as the screens change.

Add a company

Each company gets its own improvement board, modules, agent docs, and model choices at /c/<slug>/. Same passwords for now. Give the company's website and the platform reads it, writes the company's own STYLE.md (colors, type, icon, wording) which replaces the platform default style for every agent run, and restyles each module you add to it before the manager sees the preview.

Admin accounts Anetix's own people. Each has a login of their own and a code from an authenticator app. Floor and manager logins are not these.

Backup and restore

The backup is one JSON file with every platform table (companies, module versions and their files, feedback, runs, docs, reviews, diagrams) and every company's live module data, plus the admin accounts (passwords and recovery codes as hashes, authenticator secrets encrypted). The sign-in log is left out. Take one before every demo. Restore replaces everything on the instance with the file and restarts the platform; it asks for a fresh code from your authenticator, and every admin signs in again afterwards.
